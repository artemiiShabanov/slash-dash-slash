## 2026-10-25 Переход на единый воркфлоу gamedev-hub

- Вопрос: как вести slash-dash-slash так же, как остальные игры, не ломая спек-цикл `/spec` → `/build` → `/sync`.
- Варианты: (а) оставить ROADMAP.md + спеки как единственный план; (б) полностью перейти на GitHub Issues
  и выбросить ROADMAP; (в) GitHub Issues как план работ, спеки и ROADMAP как дизайн-слой.
- Решение: (в). План живёт в `docs/plan.yaml` (вехи = milestones M0-M7, задачи = 70 issues), зеркалится
  `tools/sync_plan.py`. `GDD.md`, `ROADMAP.md`, `specs/` переехали в `docs/`. Спек-цикл сохранён: задача
  из issue, которая трогает систему, начинается со `/spec` или `/build`, а `/sync` закрывает дрейф.
  Числа по-прежнему только в `slash-dash-slash/resources/*.tres`.
- Две нумерации вех сосуществуют намеренно: вехи плана M0-M7 группируют задачи по играбельным состояниям
  сборки, ROADMAP M1-M28 задаёт порядок спек внутри них. Связь записана в `plan.yaml` (`roadmap`, `specs`)
  и в таблице в начале `docs/ROADMAP.md`. Переименовывать ROADMAP под M0-M7 не стали: кросс-ссылки в
  коммитах и спеках («M5 demo question») остаются валидными.
- Размеры задач взяты из тел issues (они создавались ранней версией sync_plan.py), метки `size:` добавлены
  на GitHub. Фаза проекта: prototype, пока не сыгран этаж B целиком (M1).
